# 架构与维护边界

## 请求与身份

Astro SSR 页面只组织视图和领域服务。React Islands 承担表单、筛选、地图、日历和 Lightbox；编辑器和 EXIF 解析延迟加载。HTTP 路由位于 `src/server/routes-*`，D1 查询在领域服务，R2 访问统一经过 `src/server/storage`。

`middleware` 读取随机会话 Cookie 的哈希，解析用户和偏好，并校验写请求 Origin 与自定义 CSRF Header。未登录只在 SQL 层读取公开、已完成的训练，以及公开且未删除的旅行。媒体请求再次检查旅行权限；HTML、API 和照片使用 no-store，Service Worker 不缓存这些响应。

初始用户由维护脚本创建。账号不开放注册，不在运行时创建默认用户。数据库用户 ID 来自认证上下文，不使用客户端提交的 user_id。

## 领域与数据库

`src/types/domain.ts` 保存领域类型，`src/lib/schemas.ts` 是输入边界，`src/lib/analytics.ts` 处理纯统计计算。D1 结构由 migrations 管理，关联修改使用 D1 batch 事务；查询使用 prepared statements。

训练 UTC 时间与记录时区分开保存，统计以用户设置时区计算。单位以 kg、米、秒为内部标准。快速打卡不伪造动作组；未完成记录不进入统计。模板启动生成独立动作与组 ID。PR 从已完成组重新计算，编辑与删除不依赖过时的缓存。

旅行是地点访问记录。旅行天数为日期区间并集；没有日期的记录不计天数。城市计数只包含 city 层级。图片先写私有 R2 和 upload claim，确认存在、归属正确后才能关联为有效旅行。删除先隐藏旅行并持久化对象清理任务，定时 Worker 重试失败任务。

## 数据目录与备份

动作和地点同步只在维护命令中执行，来源固定在 `data/sources.lock.json`。动作媒体与文字分表，只有单独审核的媒体清单才可公开使用。来源版本写入 D1；世界地图另有随仓库保存的 manifest。

JSON 备份导出个人领域数据和照片引用，排除认证信息；恢复先验证 schemaVersion，按业务记录独立提交，已有 ID 跳过。照片恢复要求当前 R2 仍存在相同对象。跨账号/跨 Bucket 迁移需独立备份 D1 与 R2 并保留 ID，不是应用内 JSON 恢复的范围。

## 持续验证

GitHub 工作流执行冻结安装、领域测试与 Workers 构建。浏览器测试需先迁移并初始化本地库、同步目录、启动预览；使用临时记录并在结束后删除。`tests/e2e` 不应指向生产。

地图和列表分页控制浏览器数据量。当前个人规模的汇总服务会在服务端加载可见记录再聚合；历史规模大幅增长时应增加 SQL 聚合与查询级分页，避免整段历史的服务端内存占用。这不影响目前 SQL 层的可见性隔离。
